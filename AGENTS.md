# Suno WAV Recorder

Manifest V3 extension, plain files, no build step and no npm: it records a Suno
tab's audio with `chrome.tabCapture` and writes a PCM WAV to Downloads.

## Status

Updated 2026-11-02. Brave 156.1.98.63 (Chromium 156) loads the folder with 0
install warnings and starts `background.js`; the module, contract, encoder,
worklet, stereo and 30-minute-take suites all pass. Open: `getMediaStreamId`
needs a real toolbar click, which automation cannot supply here, so
`test/run-tests.ps1` reports that one page as
`LIMIT (one toolbar click needed: tabCapture activeTab)` rather than a pass.

## Run

- Package: `powershell -ExecutionPolicy Bypass -File package.ps1` writes the
  repository zip; `-ExtensionOnly` writes just the loadable extension.
  `package.sh` is the POSIX equivalent, but this machine has no bash, so
  `sh package.sh` fails here.
- Tests: `powershell -ExecutionPolicy Bypass -File test/run-tests.ps1`. It
  starts `test/serve.ps1` and drives headless Brave over CDP. Exit 1 on failure.
- One WAV by hand: `powershell -File test/inspect-wav.ps1
  test/out/wav-encoder-test-440hz.wav` reads the 44-byte header off disk.
- Load unpacked: `brave://extensions` > Developer mode > Load unpacked > this
  folder. Brave lives at
  `C:\Program Files\BraveSoftware\Brave-Browser\Application\brave.exe`.

## Map

- `background.js`: service worker; owns the capture session, the offscreen
  document and the download.
- `offscreen.js`, `recorder-worklet.js`, `lib/wav-encoder.js`: the tab stream,
  the Float32 tap and the WAV bytes.
- `lib/messages.js`: the six message names all three contexts share. Change it
  in every context at once.
- `popup.*` and `content.*`: two faces on those same messages.
- `test/out/` is generated by the suite; nothing in it is source.

## Decisions

- tabCapture hands over decoded audio, so the WAV is written from Float32
  chunks and is not a re-encode of the stream.
- `minimum_chrome_version` 116 stays: handing a tab stream id to an offscreen
  document needs it.
- `host_permissions` stay Suno-only. Fetching the source instead of capturing
  it would need `studio-api.prod.suno.com` and `cdn1.suno.ai`, and the clip
  payload is encrypted at rest, which is why capture is the route.
